The Problem

Manual Logbooks Can’t Protect Products

Cooling Room and Packing Room conditions were checked every few hours by operators writing numbers in a logbook. By the time a problem was recorded, it was already too late.

🕐
Critical Conditions Detected Hours Late
Temperature spikes in the Cooling Room were only discovered at the next scheduled logbook entry — not when they happened. Products inside could lose significant shelf life before any corrective action.
📊
Raw Numbers Are Meaningless Without Context
Operators knew “27°C is hot” — but had no way to know: Is mold actively growing right now? How many days of shelf life remain? Is this a heat stress risk? Those answers require scientific models, not raw readings.
⚠
Unusual Events Indistinguishable from Normal
A cooling door left open, hot product entering too quickly, or an AC failure produced spikes that were indistinguishable from normal fluctuations in a logbook. Without statistical context, every reading looked equally valid.
🏠
Two Zones Checked at Different Times
Cooling Room and Packing Room have fundamentally different risk profiles. Manual checks happened at different times by different operators — no synchronized view, no cross-zone pattern detection.

Known Limitations
No local buffer If the ESP32 loses Wi-Fi and the HTTPS POST fails, that reading is lost — there is no onboard buffer or retry logic. Connectivity gaps become visible as a break in the dashboard timeline. Operators use this as the detection signal: a gap means something to check.
Single sensor/zone One SHT31 per zone. A single point of measurement cannot capture spatial variation within a large room. A sensor placed near the door reads differently from one near the back wall.

Key Design Decisions
LTTB Downsampling
Charts cap at 500 rendered points using Largest-Triangle-Three-Buckets algorithm. Retains visual shape of the full dataset without overloading ECharts with 10,000+ rows.
API Key Security
Groq API key lives exclusively in Supabase Edge Function environment variables — never bundled in the React client. Browser makes requests to the Edge Function, not directly to Groq.
EWMA Pre-computation
EWMA + UCL/LCL computed once in useMemo before rendering, then reused across all chart series. Prevents recalculating SPC control limits on every render cycle.
Virtualized Table
HistoryTable renders only visible DOM rows regardless of dataset size. A week of 30-min readings (≈ 336 rows per zone) loads instantly — no pagination needed.
