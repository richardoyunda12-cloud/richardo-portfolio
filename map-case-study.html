Design Philosophy

The Unusual Choices

Each architectural decision was made under a specific constraint. The constraint drove the solution — not the other way around.

Decision 01
Single HTML File
The entire frontend is one HTML file — no npm, no build step, no deployment server. Sales staff open a URL on their phone and it works. Updates are a single file swap. No version mismatch, no “it works on my device” problems. The constraint of a non-technical user base forced simplicity.
Decision 02
Cloudflare Tunnel over VPS
Backend is FastAPI running on a PC server in the office, exposed via Cloudflare Tunnel — no static IP, no VPS, no router config. One-line update per morning when the tunnel URL rotates. Infrastructure cost: zero rupiah. For 6,500 data points at a non-tech company, this was the right trade-off: a VPS would be overkill and require IT budget approval.
Decision 03
Held-Karp over Greedy Nearest-Neighbor
Route planning uses the exact Held-Karp TSP solver (O(n² × 2⊃n)), not a greedy approximation. For up to 10 stores it’s fast enough and mathematically optimal. Greedy nearest-neighbor can miss the best route by 20–30% on certain store configurations. Paired with OSRM real road distances — not straight-line Haversine. Haversine is the automatic fallback when OSRM is offline.
Decision 04
watchPosition, not getCurrentPosition
watchPosition streams continuous GPS updates — the sales rep’s icon moves on the map as they drive, not just when they tap a button. getCurrentPosition would give a single snapshot. For in-field navigation, continuity matters more than battery.

Core Features

What Makes It Work

02
Held-Karp + OSRM Route Planner
Add up to 10 stores to a route basket. The system fetches a real road distance matrix from OSRM /table, then runs Held-Karp TSP to find the mathematically optimal visit order. Two OSRM servers tried in sequence with a 9-second AbortController timeout each. If both are offline, falls back to Haversine straight-line distance. Result shared to WhatsApp or opened in Google Maps multi-stop.
Exact TSP — O(n² × 2⊃n) OSRM real road matrix Haversine fallback WhatsApp share
JavaScript · app.js — Held-Karp bitmask DP // exact TSP solver 
// dp[mask][last] = min cost visiting all
// stores in `mask`, ending at node `last`
var INF = 1e9, FULL = (1 << n) - 1;
var dp = [], par = [];

// Seed: single-store paths from origin
for (var i = 1; i <= n; i++)
  dp[1 << (i-1)][i] = dist[0][i];

// Fill bitmask DP table
for (var mask = 1; mask <= FULL; mask++) {
  for (var last = 1; last <= n; last++) {
    if (!(mask & (1 << (last-1)))) continue;
    for (var nxt = 1; nxt <= n; nxt++) {
      if (mask & (1 << (nxt-1))) continue;
      var nm = mask | (1 << (nxt-1));
      var nd = dp[mask][last] + dist[last][nxt];
      if (nd < dp[nm][nxt]) {
        dp[nm][nxt] = nd;
        par[nm][nxt] = last; // track path
      }
    }
  }
}
// Backtrack par[][] to reconstruct route

Heatmap Density Mode
Toggle between individual store markers (MarkerCluster) and a heatmap. In SPD/Potensi mode, intensity = sales volume. In Retur mode, intensity = return rate. For supervisors reading geographic distribution at a glance without clicking individual stores.

Known Limitations

Honest Trade-offs

Every architectural shortcut here was a deliberate trade-off against constraint — non-technical ops team, zero IT budget, immediate deployment need.

Tunnel URL rotates Cloudflare Tunnel free tier assigns a new URL each time the tunnel restarts. Someone must update the hardcoded URL in app.js and redistribute the HTML file each morning. Acceptable for a small ops team; not scalable to hundreds of users.
Held-Karp cap at 10 Held-Karp is O(n² × 2⊃n) — exponential. At 10 stores it completes in milliseconds. At 20 it would take seconds and freeze the browser main thread. The 10-store limit is a hard constraint, not a UX choice.
No auth Anyone with the URL and tunnel address can read the store data. Acceptable because store performance data is not personally sensitive — but this would not be appropriate if the data included customer PII or financial records.
